# 3.0-I / 3.0-J frontend state contracts

Integration notes only. Do not redesign AI workspace, Window Manager, voice orb, artifact panel, Workflow Builder, or Intelligence layouts.

## Spoken WRITE (3.0-I)

Existing `pending_task` + `pending_action` + `execution_plan` remain the client contract.

| Field | Meaning |
|---|---|
| `task_state.pending_task.status` | `awaiting_confirm` until atomic claim; then `executing` / `executed` / `failed` / `cancelled` |
| `task_state.pending_action.status` | `awaiting_user` → `confirmed` or `cancelled` |
| `task_state.execution_plan.terminal_status` | `waiting_for_approval` while frozen; `completed` only after provider GET verification; `partial` if invoked but unverified |
| `task_state.execution_observations[]` | Canonical Observation; `structured.verification_status` is `verified` / `unverified` / `uncertain` |
| Identity | Email, name, provider record id, and action target in `pending_task.params.args` are frozen ActionSpec values. Do not rewrite them in the UI. |

Spoken `yes` / `Yes, create it.` confirm the bound PendingAction on the same conversation. Ambiguous speech does not execute. Repeated `yes` after `executed` is a duplicate, not a second WRITE.
