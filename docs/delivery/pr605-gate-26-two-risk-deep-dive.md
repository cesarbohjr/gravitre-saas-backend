# PR #605 — Gate 26 deep dive: orphan terminal and connector entrypoints
Date: 2026-11-05. Additive to governing modernization plan and Gate 26 tranche 1/2. Evidence level: direct branch source inspection; no claim of production coverage or passing new tests.

## Risk A — orphan orchestration terminal: source-level conclusion
`backend/app/services/chat_orchestration_service.py:1934-1974` reads persisted orchestration_run_id. If absent, it **tries to create a late run when steps exist** (lines 1935-1949), then calls `finalize_orchestration_run` if run exists (1950-1969). Only when no run exists does it fall back to `finalize_execution_outcome(...persist_run=False)` (1970-1980). Thus prior shorthand 'no run and no steps' was too narrow: **late run creation may also fail**, leaving an orphan even when steps exist. This is a real observable source branch, but not proof it occurs in production. No automatic synthetic run insertion should be made without verifying persistence failure semantics, notifications, audit and learning effects.

**Disposition:** KEEP fallback; investigate source-of-truth and operational frequency. Required tests: no-run/no-steps, late-run-create failure with steps, successful late-run creation, downstream notification/audit/learning effects, tenant scope, and no false verified completion. Add a typed orphan reason and bounded metric only after privacy review. P1 coverage gap, not certified production defect.

## Risk B — connector execution entrypoints: source-level conclusion
`chat_orchestration_service.py` has **three** direct connector execution call sites: line 1487 human-confirmed sequential step inside `write_authority('human')` (1483-1497); line 1628 parallel **read-only** batch selected only when steps are supported, need no approval and are kind `read` (1613-1637); line 1846 policy-authorized step after required approval has been intercepted (1841-1855). All three pass `own_terminal_outcome=False`, preserving orchestration as terminal owner. This is intentional branch specialization, **not evidence of three competing execution engines**.

`chat_connector_execution_service.py:1999-2034` centralizes `execute_plan` and dispatches to `_execute_plan`, including shielded execution handling. `_finalize_connector_outcome` at 3156-3193 defers speculative unadopted fanout. At 3493-3515, unverified provider acceptance is marked `verification_inconclusive`, not verified success. The connector service also has its own callers at lines 1699, 1742, 1946 and 3635, which require separate context/callsite review; do not claim global completeness from the orchestration module.

**Disposition:** KEEP all three orchestration call paths pending branch-contract tests; no consolidation or retirement approved. Required test matrix: human approval, policy authorization, revoked/denied permission, read-only parallelization, write excluded from parallel batch, `own_terminal_outcome=False` for all orchestration calls, speculative deferral, uncertain write retry and provider source-of-record verification. P0 invariant verification, not a demonstrated production vulnerability.

## Decision and exit criteria
These two questions are **resolved at the source-architecture level**: (A) orphan fallback includes late-run creation failure, (B) the three orchestration connector call sites serve distinct controlled paths with one terminal owner. They are **not closed as validated behavior** until regression tests and exact-head CI pass, and are not closed as production outcomes without approved runtime evidence. Continue caller/consumer inventory without declaring them fully audited. Update existing ECO/DEC registers with findings before any destructive change. PR #605 remains draft; no production telemetry, merge, deployment, historical reconciliation or retirement authorized.
