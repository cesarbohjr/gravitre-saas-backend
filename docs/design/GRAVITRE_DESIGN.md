# GRAVITRE_DESIGN.md

**Authority:** Subordinate to `GRAVITRE_3_0_PLUS_MASTER_SPEC.md` (§§6, 9–12, 26–27).  
**Phase:** 5 consolidation — proposal, not production token rewrite.

## Visual foundation

- **Nodus** (purchased Aceternity) = primary visual discipline — extract, do not clone every screen.
- Personality: sharp, intelligent, technical, calm, premium, precise.
- Palette character: sharp black, deep charcoal, graphite, controlled white, Gravitre emerald, restrained semantics.
- Avoid: generic AI gradients, cartoon avatars, giant rounded cards, excessive pills/glass/neon, competing colours, weak grey text.

## Logo influence

Inspect actual Gravitre logo/icon. Subtle use in selected/focus states, nodes, connection points, motion signatures, accent shapes — not logo spam.

## Typography (§9)

- Sentence case throughout (proper nouns/acronyms/user names exempt).
- Restrained scale ≈ page 22–24 / section 16 / component 14 / body 14 / secondary 13 / meta 12 / buttons 13–14 medium.
- Hierarchy via type, spacing, contrast, alignment — not containers-as-hierarchy.

## Spacing and density (§10)

One shared spacing system. Dense for tables/builders/admin; more whitespace for strategy/onboarding/empty/AI explanation.

## Containers (§11)

Reduce indiscriminate cards. Prefer surfaces, spacing, dividers, tables, lists, split panes, inspectors, canvas. Cards = meaningful grouped objects only.

## Buttons (§12)

One primary action per screen. Secondary / tertiary hierarchy. Headers are not button parking lots.

## Tokens

Keep `--np-*` / `--g-*` as authoritative local tokens. Document roles; do not introduce parallel kits.

## Icons (§27)

Nucleo primary. Avoid mixed Lucide/Heroicons/cartoon unless functional gap.
